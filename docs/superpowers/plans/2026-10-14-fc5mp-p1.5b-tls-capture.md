# fc5mp P1.5b — TLS Plaintext Capture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Capture the plaintext of the game's HTTPS/wss traffic (UbiServices login, application config with the player cap, RdV) by hooking the statically linked OpenSSL `SSL_read`/`SSL_write` inside FC_m64.dll, with credentials redacted at capture time.

**Architecture:** Two new signatures in the existing target table resolve `SSL_read`/`SSL_write` in the mapped FC_m64 image. `targets::install_all` hands the resolved addresses to `tls::install`, which creates observe-only MinHook detours. Each detour calls the original, then logs the bytes actually transferred, after a pure, host-tested `redact()` masks secrets in place (same length, so HTTP framing survives). Boot-stage markers measure how long hashing + module wait take, so we know whether early login traffic is missed.

**Tech Stack:** C++17, MinHook 1.3.3, mingw-w64, clang/ctest, Wine 11.19, Python 3.12/pytest.

**Spec:** `docs/superpowers/specs/2026-10-13-fc5mp-design.md` (P1: passive capture of UbiServices/RdV), `docs/HANDOFF.md` §2 step 2, §6a.

Prologue `B8 38 00 00 00` (`mov eax,38h`, 5 bytes) followed by `call __chkstk`-style probe. MinHook's 5-byte patch copies only the `mov`.
ABI: `int SSL_read(SSL*, void*, int)`, `int SSL_write(SSL*, const void*, int)`; return >0 = bytes transferred.

## Global Constraints

- Observe-only; originals called with untouched args; return value, `GetLastError` (curl reads `WSAGetLastError` on `SSL_ERROR_SYSCALL`) and `errno` restored.
- No on-disk game modification; signatures are verified unique in supported build `00833fae…af2`.
- **Secrets never reach disk in the clear:** `Authorization:` header values and the JSON string values of `ticket`, `sessionKey`, `rememberMeTicket`, `password`, `twoFactorAuthenticationTicket` are masked with `*` (same length).
- Existing frame kinds unchanged. New kinds: `SSL_READ_ADDR=13`, `SSL_WRITE_ADDR=14` (address markers), `TLS_WRITE=22`, `TLS_READ=23` (payload `[u64 SSL*][bytes]`), `BOOT=1` (payload `u8 stage`: 0 boot thread start, 1 version-lock passed, 2 UDP hooks live, 3 TLS hooks live).

## Review Focus

1. **Secret split across two SSL_read buffers.** A JSON value cut at the buffer end is masked to the end of the buffer (test `redact_unterminated`). A key name itself split across reads leaks the value. This is documented and accepted; tickets expire.
2. **Compressed or websocket-masked bodies** can't be redacted (gzip, client→server wss frames are XOR-masked). Captures stay sensitive. HANDOFF says so and capdump prints a reminder.
3. **Hook installed late:** login before hooks are live means no capture. BOOT markers make this visible (Task 3).
4. **`redact` on binary data** must never read or write out of bounds (tests with random bytes and patterns at the buffer edges).
5. **SSL_read returning ≤0** (WANT_READ, close) must log nothing and leave the error state intact.

### Task 1: `redact()` + TLS record encoding (pure, host-tested)
Files: `client/src/capture/redact.{hpp,cpp}`, `client/src/capture/kinds.hpp`, `client/tests/host/test_redact.cpp`, CMake.
API: `size_t fc5mp::cap::redact(uint8_t* p, size_t n)` (returns bytes masked); `std::vector<uint8_t> encode_tls(uint64_t ssl, const uint8_t* p, size_t n)` (copies, redacts the copy, caps at `kMaxPayload`).
Tests: header masked to CRLF, case-insensitive name; JSON keys (with/without spaces after `:`), multiple occurrences, unterminated value → masked to end, key at very end of buffer, non-secret keys untouched, 10k random buffers don't crash (under ASan if available), length preserved.
