# fc5mp P1.5c — Overlapped WSARecvFrom completion capture

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Capture the data of overlapped `WSARecvFrom` receives — currently logged as a marker only — so the Quazal Rendezvous (PRUDP) server→client traffic on UDP :6570 is recorded, unblocking the matchmaking RMC map.

**Architecture:** A process-wide, thread-safe registry records each in-flight overlapped recv keyed by the `OVERLAPPED*` the game passes to `WSARecvFrom` (socket + copied WSABUF list + `from`/`fromlen` out-pointers). A new observe-only MinHook detour on **`GetOverlappedResult` (kernel32)** — the only completion-reaping API FC_m64 imports (no IOCP, no `WSAGetOverlappedResult`, no completion routines; confirmed from the import table) — looks the `OVERLAPPED*` up when the game reaps a completion, and if it matches a recorded recv on the same handle, logs the delivered bytes as a normal `UDP_RECV` frame. Unknown `OVERLAPPED*`s (file I/O) pass straight through.

**Tech Stack:** C++17, MinHook 1.3.3, mingw-w64, clang/ctest, Wine 11.19, Python 3.12/pytest.

**Spec:** `docs/superpowers/specs/2026-10-13-fc5mp-design.md` (P1: passive capture of UbiServices/RdV/P2P). Evidence: `docs/research/2026-10-14-host-capture-protocol-map.md` (the :6570 recv gap), `docs/HANDOFF.md` §2 step 4, §6, §9.

## RE findings (this plan's evidence)

FC_m64 import table (via pefile): **no** `GetQueuedCompletionStatus` / `CreateIoCompletionPort` / `BindIoCompletionCallback` / `WSAGetOverlappedResult`; kernel32 imports **`GetOverlappedResult`**. ws2_32 is imported partly by ordinal and partly resolved at runtime, so the datagram APIs are already hooked by export address (P1.5a) regardless — `GetOverlappedResult` is a named kernel32 export and hooks the same way.
Signature: `BOOL WINAPI GetOverlappedResult(HANDLE hFile, LPOVERLAPPED lpOverlapped, LPDWORD lpNumberOfBytesTransferred, BOOL bWait)`. `hFile` is the socket handle for a socket completion; `WSAOVERLAPPED` is layout-compatible with `OVERLAPPED`.

## Global Constraints

- Observe-only: the original is called first with untouched args, its return value is passed back unchanged, and the caller-visible last-error is restored after any logging.
- No on-disk game modification. No new capture-frame kind: reaped overlapped recvs are logged as the existing `UDP_RECV` (21), so the Python reader needs no new decode path.
- HOOK_FAILED api-id space is shared across hook modules: 0–3 = ws2_32 datagram APIs (net_hooks), 4–5 = TLS (tls_hooks), **6 = GetOverlappedResult** (this plan). The Python reader mirrors this.
- Registry is bounded (`PendingRecvs::kMax = 512`): completions reaped some other way than `GetOverlappedResult` are never taken, so the oldest entries are evicted rather than leaked.
- The success signal for the next live capture: the `203.132.26.146:6570` peer shows `recv` packets > 0 (currently 0).

## Review Focus

1. **Non-socket `OVERLAPPED` reaped via `GetOverlappedResult`** (file/pipe I/O) must be ignored — its address was never recorded, so `take()` misses and nothing is logged (Wine test: a `FILE_FLAG_OVERLAPPED` `WriteFile` reaped via `GetOverlappedResult` produces no `UDP_RECV`). Belt-and-suspenders for the rarer same-address-reuse case: the detour also requires `hFile` == the recorded socket before logging.
2. **`GetOverlappedResult` with `bWait=FALSE` before completion** returns FALSE (`ERROR_IO_INCOMPLETE`) — must log nothing, keep the entry, and leave last-error intact (Wine test polls before the datagram is sent).
3. **Registry unbounded growth** if the game never reaps via `GetOverlappedResult` — must evict oldest past `kMax` and never exceed it (pure test).
4. **Buffer lifetime / partial fill:** only `lpNumberOfBytesTransferred` bytes are valid, spread across the recorded WSABUF list; reading must not run past the transferred length or the buffer lengths (Wine test with a 2-buffer partial fill).
5. **Last-error + reentry:** the kernel32 detour shares the net reentry guard (no double logging) and restores `GetLastError` even on the logging path (Wine test).

```cpp
#pragma once
#include <cstdint>
#include <cstddef>
#include <mutex>
#include <optional>
#include <unordered_map>
#include <utility>
#include <vector>
namespace fc5mp::net {
// Recorded at WSARecvFrom time so the datagram can be logged once the game
// reaps the completion via GetOverlappedResult. The buffer and sockaddr
// pointers are the caller's; they stay valid until the overlapped op completes
// (i.e. until the reap we act on). We copy only the small WSABUF array, never
// the datagram bytes.
struct PendingRecv {
  uint64_t sock = 0;
  std::vector<std::pair<const uint8_t*, size_t>> bufs;
  const uint8_t* from = nullptr;   // sockaddr out-ptr, filled by completion; may be null
  const int* fromlen = nullptr;    // sockaddr length out-ptr; may be null
  uint64_t seq = 0;                // insertion order, for bounded eviction
};
// Thread-safe registry of in-flight overlapped recvs, keyed by the OVERLAPPED*
// the game passed. Bounded: past kMax live entries (completions reaped some way
// other than GetOverlappedResult, so never taken) the oldest is evicted, so
// memory can't grow without bound.
class PendingRecvs {
public:
  static constexpr size_t kMax = 512;
  void record(const void* ov, PendingRecv e);     // overwrite if ov already present
  std::optional<PendingRecv> take(const void* ov); // remove + return, or nullopt
  size_t size() const;
private:
  mutable std::mutex m_;
  std::unordered_map<const void*, PendingRecv> map_;
  uint64_t next_seq_ = 0;
};
}
```

- [ ] **Step 4: Write the implementation** — `client/src/client/overlapped.cpp`

```cpp
#include "overlapped.hpp"
namespace fc5mp::net {
void PendingRecvs::record(const void* ov, PendingRecv e){
  std::lock_guard<std::mutex> g(m_);
  e.seq = next_seq_++;
  map_[ov] = std::move(e);                 // overwrite reuses the slot, no growth
  if(map_.size() > kMax){
    // evict the oldest (smallest seq); rare, only if reaps are missed
    auto oldest = map_.begin();
    for(auto it = map_.begin(); it != map_.end(); ++it)
      if(it->second.seq < oldest->second.seq) oldest = it;
    map_.erase(oldest);
  }
}
std::optional<PendingRecv> PendingRecvs::take(const void* ov){
  std::lock_guard<std::mutex> g(m_);
  auto it = map_.find(ov);
  if(it == map_.end()) return std::nullopt;
  PendingRecv e = std::move(it->second);
  map_.erase(it);
  return e;
}
size_t PendingRecvs::size() const {
  std::lock_guard<std::mutex> g(m_);
  return map_.size();
}
}
```

```cpp
// kernel32 GetOverlappedResult is how FC_m64 reaps overlapped recvs (import
// table: no IOCP / WSAGetOverlappedResult / completion routines). Observe-only.
BOOL WINAPI d_GetOverlappedResult(HANDLE h, LPOVERLAPPED ov, LPDWORD xfer, BOOL wait){
  Reentry g;
  BOOL ok = o_GetOverlappedResult(h, ov, xfer, wait);
  DWORD err = GetLastError();
  if(g.active && ok && ov){
    if(auto e = g_pending.take(ov)){
      // Guard against OVERLAPPED* reuse for non-socket I/O: only log if this
      // reap is on the same handle the recv was posted on.
      if((HANDLE)e->sock == h){
        DWORD n = xfer ? *xfer : 0;
        int flen = e->fromlen ? *e->fromlen : 0;
        std::vector<cap::Span> sp; sp.reserve(e->bufs.size());
        for(auto& bl : e->bufs) sp.push_back({bl.first, bl.second});
        emit(cap::kind::UDP_RECV, (SOCKET)e->sock, (const sockaddr*)e->from, flen,
             sp.data(), sp.size(), (size_t)n);
      }
    }
  }
  SetLastError(err);
  return ok;
}
```
