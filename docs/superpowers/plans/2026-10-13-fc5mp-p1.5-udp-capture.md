# fc5mp P1.5a — Winsock UDP Traffic Capture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the injected client actually record the game's UDP traffic (Storm P2P + punch) to the capture file, plus a Python reader that turns a capture into a readable summary, so the Phase A smoke test and Phase B co-op capture produce usable data.

**Architecture:** Pure, host-tested encoders (`capture/udp_frame`) turn a socket + peer sockaddr + scatter/gather buffers into one framed record. A single process-wide capture sink (`client/sink`) replaces the per-call `Writer` so address markers and traffic share one file. Windows-only detours (`client/net_hooks`) wrap the four ws2_32 datagram APIs by export (known ABI, no FC_m64 signatures needed), log after the real call, and preserve the caller's last-error. A Python reader (`fc5analyze/capture.py` + `capdump.py`) decodes the framing.

**Tech Stack:** C++17, MinHook 1.3.3, mingw-w64 (DLLs), clang + ctest (host tests), Python 3.12 + pytest via `uv`.

**Spec:** `docs/superpowers/specs/2026-10-13-fc5mp-design.md` (P1 row: passive capture of UbiServices/RdV/Storm traffic), `docs/HANDOFF.md` §2 step 2, §6.

## Global Constraints

- No DRM bypass; no on-disk modification of game files. Hooks are runtime-only, in our injected DLL.
- Observe-only: every detour calls the original with unmodified arguments and returns its result unchanged.
- Capture framing stays `[u64 ts_ns][u8 kind][u32 len][len bytes]` little-endian (P1 `record.cpp`).
- Existing kinds keep their values: 10/11/12 address markers, 250 module-timeout, 251 sig-missing.
- Pure logic must build under both host clang and mingw; Windows code guarded by `_WIN32`.
- TLS (static OpenSSL in FC_m64) is **out of scope** — that is P1.5b.

## Review Focus

1. **Caller-visible last-error clobbered** — logging (fopen/fwrite/alloc) can change `GetLastError`; a game checking `WSAGetLastError()` after `SOCKET_ERROR`/`WSA_IO_PENDING` must see the original value. Every detour saves and restores it (Task 3; reviewed by reading — no host harness for ws2_32).
2. **Recv length < buffer length / multi-buffer WSABUF** — only the received byte count may be logged, gathered across buffers in order (Task 1 test `gather_partial_multi`).
3. **Null / short / unknown sockaddr** (connected sockets pass `to=nullptr`; `fromlen` may be null) — must not read out of bounds; records family 0 (Task 1 tests `peer_null`, `peer_short`, `peer_unknown_family`).
4. **Huge datagram / bogus length** — stored payload capped at `kMaxPayload`, real length kept in `orig_len` (Task 1 test `truncates_to_cap`).
5. **Crash mid-capture leaves a torn final frame** — the reader returns all whole frames and reports trailing bytes instead of throwing (Task 4 test `torn_tail`).

**Interfaces:**

  - `struct Peer { uint16_t family; uint8_t port[2]; uint8_t addr_len; uint8_t addr[16]; }`

Record payload layout (little-endian): `[u64 socket][u16 family][2 bytes port, network order as on the wire][u8 addr_len][addr_len bytes][u32 orig_len][stored payload]`. Families: 2 = IPv4 (addr at sockaddr+4, 4 bytes), 23 = Windows IPv6 (addr at sockaddr+8, 16 bytes); anything else → family kept, addr_len 0.

### Task 3: Winsock datagram detours

**Files:**
- Create: `client/src/client/net_hooks.hpp`, `client/src/client/net_hooks.cpp`
- Modify: `client/src/client/dllmain.cpp`, `client/CMakeLists.txt` (add source; link `ws2_32`)

**Interfaces:**
- Consumes: `hook::create/enable_all`, `client::sink()`, `cap::peer_from_sockaddr`, `cap::encode_udp`, `cap::kind::*`
- Produces: `fc5mp::net::install()` — creates hooks on ws2_32 `sendto`, `recvfrom`, `WSASendTo`, `WSARecvFrom`; logs `HOOK_FAILED(api id)` for any it can't resolve/create. API ids: 0 sendto, 1 recvfrom, 2 WSASendTo, 3 WSARecvFrom.

Detour rules (all four):
- Call original first with untouched args; capture `GetLastError()` immediately; restore it before returning.
- Thread-local re-entry guard: nested calls (if logging ever touched sockets) pass straight through.
- First call per API → `API_SEEN(api id)` (tells us which API Storm actually uses).
- `sendto`: log `UDP_SEND` when `r > 0`, total = r.
- `recvfrom`: skip if `flags & MSG_PEEK`; log `UDP_RECV` when `r > 0`, peer from `from`/`*fromlen` (null-safe).
- `WSASendTo`: log `UDP_SEND` when `r == 0` or last-error `WSA_IO_PENDING` (buffers are already filled at call time), total = sum of buffer lengths.
- `WSARecvFrom`: read input flags before the call; skip MSG_PEEK. `r == 0 && recvd` → log `UDP_RECV`, total = `*recvd`. `SOCKET_ERROR` + `WSA_IO_PENDING` → `RECV_PENDING(u64 socket)`, capped at 64 markers (completion-side capture deferred until Phase A shows Storm uses overlapped recv).
- `dllmain` Boot order: version-lock → `hook::init` → `net::install` → `hook::enable_all` (UDP live immediately) → `targets::install_all` (may wait ≤20 s for FC_m64).
